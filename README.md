# 蝦皮擷取器 Shopee Capture

自動擷取蝦皮聯盟合作分潤商品：你在蝦皮商品列表畫面點懸浮視窗的
「自動」按鈕，程式會依序點開列表中的商品、觸發分享、複製推廣連結、
截圖商品、關閉面板、回到列表、換下一個商品，直到達到你設定的目標數量。
每一筆結果統一存到 `Download/CaptionQueue/{時間戳記}/` 資料夾，
供另一個 App（文案/影片生成 App）讀取處理。

也保留單次手動擷取按鈕（「擷取」），可以針對單一商品手動觸發，
不想跑全自動迴圈時使用。

## ⚠️ 關於帳號風險（務必先讀）

這個 App 用「無障礙服務」模擬連續點擊、滑動來自動操作蝦皮 App，
本質上就是平台會嘗試偵測的「非人類操作模式」。跟只在你主動點擊當下
執行單一動作的半自動模式相比，**連續自動化的行為模式更容易被判定異常**。

程式加了隨機延遲區間（在設定裡可調），只是讓操作節奏不那麼規律，
**不代表能規避偵測機制**。實際使用建議：
- 目標數量抓保守一點，不要一次跑幾十件
- 觀察帳號有沒有出現任何異常提示（例如驗證碼、限制訊息），
  一發現苗頭不對就先停用「自動」模式，改回手動
- 這是你已經評估過、自行承擔的風險決定，此處僅再次書面提醒

## 這個 App 仍然不會做的事
- **不會**自動搜尋關鍵字或選擇要瀏覽哪個分類（這段仍需要你手動先滑到商品列表畫面）
- **不會**自動購買或下單
- **不會**在你沒有主動點擊懸浮按鈕的情況下於背景默默執行任何動作

## ⚠️ 關於無障礙服務的讀取範圍（重要變更）

早期版本把無障礙服務限定在只能讀取「蝦皮」相關套件的畫面。
但實測發現部分地區（例如菲律賓）的聯盟行銷介面是獨立的 App，
套件名稱不確定，如果限制清單裡沒列到，服務連「偵測套件名稱」
這個除錯工具本身都讀不到畫面（系統的套件白名單限制是雙向鎖死的）。

因此**目前版本移除了套件白名單限制**，服務技術上可以讀取「當下最上層任何 App」
的畫面內容。這是為了解決先有雞先有蛋的問題（不知道套件名稱、就沒辦法把它加進白名單）。

**這不代表 App 會偷偷讀取或上傳其他 App 的內容** —— 所有動作（截圖、點擊、
讀取剪貼簿）仍然只在你主動點擊懸浮按鈕的那一刻才執行，其他時間服務完全被動、
不做任何事。但技術上「能讀」跟「有沒有做」是兩件事，如果你介意這個權限範圍變廣，
可以參考下面「找到套件名稱後重新限制範圍」的做法，把範圍縮小回去。

### 找到套件名稱後，建議重新限制範圍

1. 打開這個 App 的懸浮視窗，切到你要用的聯盟行銷 App／頁面
2. 點懸浮視窗的「**偵測**」按鈕，會跳出通知顯示目前畫面的套件名稱
3. 把這個套件名稱記下來，之後可以在 `accessibility_service_config.xml` 裡加回：
   ```xml
   android:packageNames="com.shopee.tw,你剛剛偵測到的套件名稱"
   ```
4. 改完重新建置、安裝，就能把讀取範圍限制回原本設計的「只限蝦皮相關 App」

## 使用方式

1. 打開這個 App，照畫面上三個步驟設定：
   - 開啟無障礙服務
   - 允許「顯示在其他 App 之上」權限
   - 啟動懸浮按鈕
2. 切到你要用的聯盟行銷 App／頁面，點懸浮視窗的「**偵測**」按鈕確認套件名稱
   有沒有正確被讀到（如果通知有正常跳出畫面套件名稱，代表服務運作正常）
3. 在「蝦皮地區」選擇你使用的版本（目前支援台灣、菲律賓），
   選菲律賓會自動加入當地語言的按鈕文字候選（例如 Filipino 版的
   「Kopyahin ang link」複製連結字樣），提高辨識成功率，
   也讓商品價格篩選能正確辨識披索符號 ₱
4. 在「全自動擷取設定」調整目標數量與延遲區間（有記憶，設定一次即可），
   也可以設定篩選條件：**分潤率、商品價格、已售出數量、已推廣者數量**，
   每項都可以只設最低、只設最高、或兩者都設，留空代表不限制。
   不符合條件的商品會被自動跳過、不計入目標數量，換下一個繼續判斷。
   也可以設定**篩選時間上限（分鐘）**，時間到了還沒湊到目標數量會自動停止，
   並跳出獨立通知＋震動提醒（比一般 Toast 明顯，避免你切到別的畫面錯過）。
   「最大嘗試次數限制」跟「篩選時間上限」都各自有獨立開關，
   可以只開一個、兩個都開、或兩個都關（兩個都關時只靠「列表滑到底」
   這個天花板機制停止，請自行斟酌風險）
5. 切換到蝦皮 App，手動滑到你想推廣的商品**列表畫面**（例如「聯盟合作」的商品分頁，
   或搜尋結果列表），畫面上會看到含價格的商品卡片
6. 點懸浮視窗的「自動」按鈕，開始自動迴圈：
   - 點開一個商品 → 觸發分享 → 等分潤分享面板出現 → 點「複製連結」→
     讀取剪貼簿 → 截圖 → 關閉面板 → 返回列表 → 換下一個商品
   - 懸浮按鈕文字會顯示進度，例如 `3/10`
   - 想中途停止，再點一次「自動」按鈕即可
7. 也可以只用「擷取」按鈕做單次手動擷取（滑到單一商品的分享面板後點擊）
8. 回到本 App 首頁可以看到擷取清單

## 資料存放位置
```
/storage/emulated/0/Download/CaptionQueue/{時間戳記}/
  ├── image.jpg      商品截圖
  └── meta.json       {"productName": "...", "promoLink": "...", "capturedAt": ...}
```

這個資料夾是給第二個 App（生成/發布器）讀取用的工作佇列。

## 遠端設定檔（因應蝦皮改版）

蝦皮 App 改版可能導致按鈕文字、畫面結構改變，讓擷取失效。
本 App 會在啟動時嘗試從一個 GitHub raw JSON 網址讀取最新比對規則，
你只要更新那份 JSON、push 上去，App 下次啟動就會抓到新規則，
**不需要重新編譯打包**。

目前程式碼裡的網址是佔位符，記得改成你自己建立的設定檔 repo 網址：
```kotlin
// RemoteConfigLoader.kt
private const val CONFIG_URL =
    "https://raw.githubusercontent.com/YOUR_GITHUB_USERNAME/shopee-capture-config/main/match_rules.json"
```

設定檔格式範例：
```json
{
  "copyLinkButtonTexts": ["複製連結", "Copy link"],
  "productImageResourceIdKeywords": ["image", "img", "photo"],
  "shareSheetTitleTexts": ["分享以獲得分潤金"],
  "shareButtonDescriptors": ["分享", "Share"],
  "priceIndicatorPrefixes": ["$", "₱", "RM", "Rp"]
}
```

如果自動擷取常常「找不到分享按鈕」或「分享面板未出現」，通常代表
`shareButtonDescriptors` 或 `shareSheetTitleTexts` 需要調整，
可以先在設定檔裡加入更多候選字串試試。

## 自動擷取何時會停止

三種情況任一發生就會停止，不會無止盡跑下去：

1. **達到目標數量**：正常完成，沒有特別提醒，懸浮按鈕文字恢復成「自動」
2. **達到最大嘗試次數**：上限是「目標數量 × 6」且至少 30 次，每點開判斷一個商品
   （不管成功、被篩選跳過、還是失敗）都算一次嘗試。這是避免篩選條件太嚴格時，
   程式在列表裡無止盡翻找、卡住不停止的保護機制。達到這個上限時會跳出
   明顯提醒（獨立通知＋震動），因為代表你設定的篩選條件可能太嚴格，
   或者這批商品裡符合條件的本來就不多
3. **達到篩選時間上限**（如果你有設定）：時間到了直接停止，同樣跳出明顯提醒。
   這個機制跟「最大嘗試次數」是同時生效的，任一個先達到就停止 —— 次數上限
   保證不會無限次操作，時間上限則讓你對「大概要等多久」有更明確的掌握
   （因為每次判斷商品實際花費的時間會受頁面載入速度影響，次數固定不代表
   時間固定）

另外「列表滑到底、真的沒有更多商品可判斷」也會停止，這種情況不會跳出特別提醒，
只會在 Toast 顯示一般完成訊息。

## 根據菲律賓版實際截圖修正過的內容

以下是對照真實 App 截圖後確認／修正的比對規則：

- **分潤率**顯示格式是 `Comm Rate 16.5%`（列表）或 `COMMSXTRA 7.5%`（詳情頁），
  已加入對應的解析規則
- **已售出**顯示格式是 `10K+ sold`（K 縮寫），不是完整數字，已支援 K/M 縮寫換算
- **已推廣者**顯示格式是 `11.5K+ Affiliates Promoted`，同樣支援縮寫換算
- **分享按鈕**文字是 `Share to Earn`，**分享面板標題**是 `Share to Earn Commission`，
  **複製連結按鈕**文字是 `Copy Link` —— 這三項原本的預設規則已經涵蓋，不用調整
- 這個聯盟行銷介面（底部導覽列 Offer / Conversions / Income / Account）
  看起來是**獨立的聯盟行銷入口**，不是一般購物介面，套件名稱不確定，
  所以移除了套件白名單限制（見上方「關於無障礙服務的讀取範圍」說明）

## 已知限制
- 商品截圖需要 Android 11（API 30）以上才能使用系統的 `takeScreenshot()` API，
  低於這個版本的手機只能存到文字資料（商品名稱、連結），沒有商品圖
- 商品名稱擷取邏輯是抓畫面上「長度落在合理範圍的文字節點」，
  是一個近似猜測邏輯，不保證每次都準確抓到正確標題
- 「商品卡片」的判斷邏輯（大小 + 含價格符號文字）是近似猜測，
  如果列表版面跟預期差異很大，可能誤判或漏抓，建議先用少量目標數量測試
- 篩選條件（分潤率、價格、已售出、已推廣者）是用文字比對規則從畫面上
  解析數字，如果某個數值讀不到，該商品會被視為「不通過篩選」而跳過
  （保守處理，避免篩選條件形同虛設）。如果發現大量商品被誤判跳過，
  代表畫面上的文字格式跟解析規則對不上，需要調整
  `ShopeeAccessibilityService.kt` 裡 `extractProductMetrics` 的正規表達式
- 自動化迴圈跑一輪後建議人工檢查一次擷取清單，確認沒有明顯錯誤資料

## 建置方式
跟其他專案一樣，用 GitHub Actions 雲端編譯：push 到 `main` 分支後，
到 Actions 分頁等待 `Build APK` 跑完，下載 Artifacts 裡的
`shopee-capture-debug`，解壓縮後安裝 `app-debug.apk`。
